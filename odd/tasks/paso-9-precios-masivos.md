# Paso 9 del Roadmap — Edición múltiple de precios en el catálogo

Objetivo: permitir modificar masivamente precios (Detal/Mayor), márgenes y costos de un conjunto de productos (selección por checkboxes/rango y "seleccionar todos los filtrados"), con vista previa "Antes vs Después" y aplicación atómica vía `BulkUpdatePricesAsync`, respetando el régimen multi-moneda vigente (Bs.S canónico por techo con la tasa del día, 8.104) y las reglas de herencia de precios de agrupadores de variantes. Tramo 8.181. Branch: V0.15. Entrega: work units locales en V0.15 (push/PR = decisión del mantenedor). RDD: off (clone-local, igual que 8.179/8.180). Tests: build `dotnet build CommandCenter.slnx -c Release`; carriles `--filter "FullyQualifiedName~Bulk|FullyQualifiedName~Product|FullyQualifiedName~Inventory|FullyQualifiedName~Pricing"`; web n/a (sin cambios web).

Nota WIP: el worktree contiene el WIP ajeno de ingesta unificada (~69 archivos) que NO se toca; los commits de este tramo se hacen por hunks/blobs para dejarlo intacto. El bundle `Backend.API/wwwroot` NO se regenera (regla vigente hasta cerrar el WIP).

## Specs

Fuente: `docs/Ideas.txt` Paso 9 (líneas 425-478, sincronizado 2026-10-13) + nota del roadmap (línea 427) + exploración L2. Supuestos marcados.

- **S1 (Contrato backend — preview y apply)**: DTOs `BulkPriceUpdateRequestDto` (selección: `ProductIds` 1..1000 **o** `Filter` + `SelectAllFiltered`; `Operations[]` con `{Field, Mode, Value}`) y rutas `POST /api/products/bulk-prices/preview` (sin escrituras: filas antes/después por campo + omitidos con motivo + totales) y `POST /api/products/bulk-prices/apply` (`BulkUpdatePricesAsync`: UNA transacción con execution strategy — precedente `InventoryService.Import.cs:38-64`; all-or-nothing; 400 ante valor resultante negativo, mayor>detal o selección >1000; 409 ante conflicto de concurrencia con rollback total; invalidación de cachés de producto post-commit `InvalidateAllProductCaches`). RBAC: Admin/Manager (controller + `CanMutateCatalog`), misma política que el resto de mutaciones del catálogo. Controller como partial nuevo (`ProductsController.BulkPrices.cs`, molde `ImportExport.cs`).
- **S2 (Semántica de operaciones)**: `Field` ∈ {RetailPrice, WholesalePrice, RetailMargin, WholesaleMargin, CostPrice}; `Mode` ∈ {SetFixed, IncreasePercent, DecreasePercent} (porcentaje sobre el valor actual). Reuso interno de las MISMAS rutinas del update individual (`ValidateAndCalculateProductPrices` `InventoryService.cs:117-201`, `RoundPriceUp`, `ToBsSCeiling`): precio fijo manda; margen recalcula precio = costo×(1+margen) con redondeo vigente; toda operación que cambie el precio USD recalcula `PriceBsS` canónico con la tasa del día (`InventoryService.ExchangeRate.cs:11-54`). `LastConversionRate` no se escribe (igual que create/update actuales).
- **S3 (Agrupadores/variantes)**: guardas idénticas al update individual (`ProductUpdates.cs:10-81`, banderas de grupo inmutables): grupos con `HasIndependentPricing` (precios propios en cero) se EXCLUYEN de operaciones de precio con motivo legible; una operación sobre un header heredado propaga a sus hijos como el update individual (`PropagateGroupPricingToVariantsAsync:166-204`), y todo hijo cuyo precio USD cambie recalcula su Bs.S canónico; hijos con precios independientes se ajustan solo si se seleccionan explícitamente. El preview lista los omitidos con motivo.
- **S4 (Vista previa determinística)**: preview y apply comparten el mismo motor de cálculo (test de consistencia preview==apply); la tabla muestra por producto y campo afectado: valor antes → después (USD y Bs.S), omitidos con motivo, y totales (seleccionados / actualizados / omitidos).
- **S5 (WPF)**: `InventoryView` gana columna de checkboxes con estado de selección persistente entre páginas + botón "Seleccionar todos los filtrados" (modo filtro del contrato); botón "Editar precios" (habilitado con `CanMutateCatalog` y selección ≥1) abre `BulkPriceEditDialog` (MVVM vía `IDialogService`): configuración de operaciones (campo/modo/valor; validación: ≥1 operación, sin negativos), "Vista previa" → grilla comparativa con omitidos, "Aplicar" con confirmación → toast + refresco del catálogo (reload + `CatalogUpdatedMessage` in-process). Async no bloqueante (CommunityToolkit, sin async void; patrones de `wpf-performance-and-ui`: modal isolation, hotkeys). Tests de VM: selección, todos-los-filtrados, flujo preview→apply, errores.
- **S6 (Alcance de clientes — SUPUESTO)**: Desktop WPF (el catálogo administrable). Web queda FUERA de este tramo (Web.Frontend no tiene CRUD de producto; la edición masiva es operación de gestión, no de caja). El backend queda client-agnóstico para habilitarlo después si el mantenedor lo pide.
- **S7 (Proceso)**: build slnx 0/0; carriles `~Bulk|~Product|~Inventory|~Pricing`; suite completa por partes al cierre; verificación independiente read-only por convención; ANEXO 8.181 en `docs/reporte.txt` + `docs/Ideas.txt` (Paso 9 `[x]`) + commit docs; commits por work units en V0.15 con staging por hunks/blobs (WIP intacto); bundle NO regenerado (residual heredado del WIP).
