2. HALLAZGOS ESPECÍFICOS DEL MÓDULO
--------------------------------------------------------------------------------
[H-CORE-1] Modelo de roles incompleto e inconsistente.
  UserRole define solo Admin, Cashier y Driver; "Manager" NO existe, aunque la
  API y el cliente lo referencian (ver H-API-1). Además existen controles que
  tratan al sistema como "Admin vs Cajero" mientras el enum incluye "Driver"
  (pendiente de Logistics, módulo vacío). Unificar el modelo de roles y
  permisos ANTES de seguir agregando [Authorize(Roles=...)].

[H-CORE-2] Secretos por defecto dentro de clases de configuración.
  Core/Configuration/SystemSettingsOptions.cs define valores por defecto
  "Admin", "Admin123!" (AdminSeedPassword) y URL de actualizaciones
  http://localhost:5000/updates/. Aunque el seed real lee IConfiguration (y
  lanza si falta la contraseña en producción), el default en el POCO es un
  secreto hardcodeado que puede colarse si alguien enlaza las opciones
  directamente. Eliminar el default del password (dejar vacío y validar).

[H-CORE-3] Entidad User sin campos para endurecer autenticación.
  No hay FailedLoginAttempts, LockoutEnd, LastPasswordChange, LastLogin ni
  email. Implementar bloqueo por cuenta (A5 global) exige migrar estas
  columnas. PasswordHash contiene el hash autodescriptivo "PBKDF2$..." (bien)
  pero el hasher acepta comparación legacy en texto plano (ver PasswordHasher
  en Backend.API) mientras existan filas legacy.

[H-CORE-4] Logging duplicado, sin rotación y con doble lock.
  Existen DOS loggers estáticos con la misma mecánica: AppLogger (start.log,
  crash.log, db-errors.log, security-audit.log, warn.log) y ClientStateLogger
  (client-resilience.log), cada uno con lock propio y File.AppendAllText por
  línea (abre/cierra el archivo en cada escritura). Ninguno rota ni limita
  tamaño: crecen indefinidamente en producción (M3 global). Unificar en un
  solo servicio con rotación.

[H-CORE-5] Claves de caché no centralizadas del todo.
  CacheKeys.cs define solo 3 claves (payment methods y cash drawer session);
  InventoryService mantiene sus propias claves con interpolación de strings
  ("product_sku_{...}", "product_quick_{...}", "variant_options_{id}") y la
  constante privada ExchangeRateCacheKey. Centralizar TODAS las claves en
  CacheKeys para evitar colisiones/olvidos de invalidación.

[H-CORE-6] TimeZoneHelper duplicado en Sales.Module/Helpers.
  Core/Helpers/TimeZoneHelper.cs y Sales.Module/Helpers/TimeZoneHelper.cs
  coexisten (el segundo con API GetTimeZone(id) para la zona seleccionada).
  Riesgo de divergencia; mover la variante "SelectedTimeZoneId" a Core.

[H-CORE-7] DTOs sin validación declarativa.
  La mayoría de DTOs de Core son clases planas sin DataAnnotations; la
  validación vive en controladores/servicios con ifs manuales repetidos (y a
  veces olvidados). Product (entidad) sí trae [Required]/[Range]/[StringLength]
  razonables. Definir DTOs de entrada con anotaciones y usar el filtro global.

[H-CORE-8] Entidades "huérfanas" y acoplamiento.
  Core/Entities/Order.cs parece sin uso real (buscar referencias antes de
  asumir); Product mezcla muchas responsabilidades de variantes/precios
  (decenas de propiedades), reflejando la lógica tipo "god" de InventoryService.
  La entidad Product en Core la consumen también Sales (para cálculos),
  generando dependencia de Sales.Module hacia datos de inventario que debería
  llegar por DTO (ProductSnapshot en ventas atenúa esto).

3. FORTALEZAS DEL MÓDULO
--------------------------------------------------------------------------------
- Dinero SIEMPRE en decimal y reglas de redondeo centralizadas
  (PricingCalculator) con precisión digital/efectivo diferenciada.
- TimeZoneHelper de Venezuela con resolución multiplataforma (IANA/Windows) y
  fallback UTC-4.
- BarcodeValidator robusto: formato 4-15 alfanuméricos, rechazo de QR/URLs y

- BaseEntity con CreatedAt/UpdatedAt consistente entre entidades.
- CacheMetrics con Interlocked (thread-safe) y exponibles vía health/metrics.
- InventoryMessages centraliza mensajes de validación de inventario.
