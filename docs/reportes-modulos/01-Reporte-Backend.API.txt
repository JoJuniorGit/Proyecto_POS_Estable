--------------------------------------------------------------------------------
1. RESUMEN DE EVOLUCIÓN ARQUITECTÓNICA (FASES 1 A 4)
--------------------------------------------------------------------------------
Backend.API constituye el núcleo de servicios del sistema. Durante el plan de remediación
se consolidaron las siguientes mejoras críticas:

1. Estandarización Total de Errores RFC 7807 (ERR-01 ✅, Commit 1e8b29f):
   - GlobalExceptionHandlerMiddleware.cs estandariza ProblemDetails con campos duales
     ('message' / 'Message' y 'traceId' / 'TraceId') para compatibilidad hacia atrás.
   - Soporte para PostgreSQL SQLSTATE 23502 (violación de restricción NOT NULL) mapeado a HTTP 400.
   - Mapeo de errores de unicidad (23505 → 409 Conflict), claves foráneas (23503 → 400 Bad Request)
     y concurrencia (DbUpdateConcurrencyException → 409 Conflict).
   - Retiro de catches genéricos en ProductsController y ReservationsController.

2. Inicialización DDL Asíncrona y Segura (A7 ✅, Commit 492f038):
   - Program.cs ejecuta await _invDb.Database.MigrateAsync() y await _salesDb.Database.MigrateAsync()
     al inicio. Las comprobaciones defensivas posteriores se reescribieron contra
     information_schema.tables e information_schema.columns sin sentencias destructivas.

3. Endurecimiento de Seguridad Web y CSP (C4 / SEC-09 ✅, Commit 686f0cd):
   - SecurityHeadersMiddleware.cs aplica estrictamente script-src 'self' en producción,
     eliminando 'unsafe-inline'.

4. Mantenimiento y Purga de OutboxMessages (PERF-05 ✅, Commit 686f0cd):
   - OutboxProcessorJob.cs incluye PurgeProcessedMessagesAsync en lotes de 1.000 para
     mensajes con Status='Processed' y más de 7 días de antigüedad, con timeout y auditoría forense.

5. Saneamiento de Endpoints Anónimos (SEC-08 ✅, Commit 2c4be32):
   - HealthController.cs saneado: se retiraron Environment.MachineName y ex.Message.
   - AuthController.cs unificó respuestas de fallo a HTTP 401 "Credenciales inválidas." (A5 ✅).

3. FORTALEZAS DEL MÓDULO
--------------------------------------------------------------------------------
- Pipeline de middleware robusto: GlobalExceptionHandler -> SecurityHeaders -> RateLimiter ->
  SecurityStampValidation -> Authentication/Authorization.
- Protección de endpoints monetarios críticos con [RequireSecurityStampValidation].
- Advisory locks de PostgreSQL en BcvExchangeRateJob para evitar colisiones de scraping concurrente.
- Rate Limiting estricto para autenticación (10 req/min) y API general (200 req/min).

--------------------------------------------------------------------------------
4. RECOMENDACIONES FUTURAS

- Retirar los bloques catch locales con ex.Message en DailyClosureController, ShiftsController
  y ExchangeRateController.
- Añadir puertos 80 y 443 al allowlist por defecto de CORS para redes privadas.
