2. NUEVOS HALLAZGOS REV. 8.0 (Web.Frontend)
--------------------------------------------------------------------------------
[8W-CR2] CRÍTICO — JWT persistido en localStorage (robo XSS).
  - AuthContext.jsx:9 (localStorage.getItem('token')), :37-38 (setItem/removeItem),
    api.js:159-171 (Bearer), :86-97/:121-147 (setCustomBaseUrl + allowlist de bypass
    para endpoints anónimos). Un XSS cualquiera (accesible al servir por HTTP 5000 sin
    Secure) extrae el token de caja. localStorage NO es context-aislado ni tiene puerta
    HttpOnly.
  - Fix (prioridad 1): mover el token a cookie HttpOnly Secure SameSite=Lax (ya hay
    middleware cookie en backend) o usar un ServiceWorker con canal masivo; añadir CSP
    estricta (script-src 'self'; object-src 'none'; base-uri 'self'), escapar claves en
    el API y endurecer el bundle.

[8W-C1] ALTO — Base-URL del API / CORS credentialed con AnyPort en localhost
  (cross-backend 01 [8W-C1]): el allowlist (localhost:*) acepta cuantas webs con guion
  en la misma host quieran robar el token cookie pos_jwt (SameSite=Strict no protege
  contra crosses de host distinto dentro del mismo "site" localhost). Combinado con
  [8W-CR2], la superficie es máxima.
  - Fix: restringir origin del SPA a hosts/puertos exactos; cookie HTTP-only SameSite; y
    mover el emparejamiento a token efímero+pinned.

[8W-ZT] MEDIO-ALTO — Zero-Trust: el checkout web aplica la validación de pago y el
  cálculo de vuelto por UI (CheckoutModal.jsx:76-82 redondea y forma el payload), y
  usa el patrón server-flow para consumir endpoints. El backend revalida precios/cambio,
  pero el cálculo visual informativo puede divergir del real por centavos en mixto.
  - Fix: consumir un endpoint /checkout/preview que devuelva los importes canónicos.

[8W-M1] MEDIO (persistente) — UX hace heavy use de window.confirm/alert bloqueantes en
  flujos de caja (descartar carrito, guardar configuración local, rechazo de escaneo)
  — fuera de MVVM y con riesgo de doble pulsación; migrar a modales in-app reutilizables.

[8W-M2] MEDIO — Mismatch de trap de escáner vs. input manual:
  SearchBar.jsx:104 captura datos como si vinieran del lector mientras que
  useScannerTrap.js:33 define el umbral; hay caminos donde el wedge puede entrar con un
  caracter de 40 ms y generar SKUs truncados sin feedback de error (solo carga).
  - Fix: unificar un único guardián de escaneo (useScannerTrap) y validación del SKU.

[8W-B1] BAJO — Hotkeys sin gating en modales activos (Enter/teclado numérico) cuando un
  modal está abierto; validate en usePosHotkeys con locus de modal cerrado.

[8W-B2] BAJO — base-uri/form-action/CSP mejorables: el bundle compila con strict CSP
  pero conviene elevar a meta http-equiv también y 'strict-dynamic' para PWA.

[8W-B3] BAJO — PWA offline caching (Workbox) puede cachear respuestas del API con tokens
  en el scope if Activo sin routing DB; asegurar que el runtime cache NO captura
  endpoints /api/* con credenciales.
